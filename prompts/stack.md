You choose the technology stack for a rebuild of an app. You work in the current folder only. Read `input/features.md` (what the app does) and `input/technology.md` (the current stack). Do not look anywhere else on this machine for the app or its source.

Write `stack.md` in the current folder. Start from the current stack in `input/technology.md` and change it only with a reason, measured against: simplicity, compatibility, speed and performance, and UX. Always consider the simplest option the platform itself offers before adding a library or a framework.

stack.md has these sections:
- Chosen stack: languages, frameworks, libraries, storage, build and test tools, each with a one-line reason. Include the backend.
- Changes from the current stack: each change and the reason, or "none".
- Considered and dropped: each option you looked at and why it lost.

Write behaviour and technology names only. No code blocks, no file paths of source files, no copied text.
